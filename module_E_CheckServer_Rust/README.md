# 모듈 E: Windows 서버(AIRBOOK-FAS) 점검·실시간 감시 — Rust 확장판

- **과목:** 인공지능특론세미나 (01반) 기말과제
- **학교:** 한양사이버대학교 일반대학원 기계IT융합공학과
- **학번 / 이름:** 2025300378 / 이민호

모듈 B(Python, `python/CheckServer.py`, v2.5)의 관제 프로그램을 Rust(egui)로 다시 작성하고, 프로세스 관계도·작업 스케줄러·네트워크 연결·핑 점검 탭과 점검 스크립트 편집 기능을 추가한 프로그램입니다. 모듈 D(`module_D_AIRBOOK-FAS/`)가 모듈 B의 기본 기능을 옮긴 버전이라면, 모듈 E는 그 위에 기능을 확장한 버전입니다.

## 상태

- **소스:** 작성 완료 (`src/main.rs`, 약 3,400줄, 단일 파일)
- **실행 파일:** 루트의 `checkserver.exe`(빌드 산출물)가 있습니다. 배포용 폴더(`배포용/`)와 사용설명서는 아직 없습니다.
- **재빌드 제한:** `src/main.rs`가 `../assets/checkPC.bat`, `../assets/checkPC.ps1`을 `include_bytes!`로 포함하지만, 이 두 파일이 저장소에 없습니다. 이 상태로는 `cargo build`가 실패합니다. 파일을 `assets/`에 추가하거나 해당 항목을 제거해야 합니다. (자세한 내용은 "알려진 제한" 참고)

## 구성

| 경로 | 내용 |
|---|---|
| `src/main.rs` | GUI(egui), 수집, 점검 배치 실행, 설정, 핑·네트워크·작업 스케줄러 조회 전체 |
| `userset.json` | 설정 파일 (exe와 같은 폴더에 둠) |
| `F100-*.bat` | 내장 점검 스크립트 원본 (`include_bytes!`로 exe에 포함) |
| `checkserver.exe` | 빌드 산출물 |
| `python/CheckServer.py` | 모듈 B의 Python 원본 (비교용) |
| `build/checkserver/` | Python 원본을 PyInstaller로 빌드했을 때 생긴 중간 산출물 |
| `Cargo.toml`, `Cargo.lock` | 의존성 (eframe 0.37, sysinfo 0.40, egui_extras, csv, chrono, serde_json 등) |

## 기능

탭은 11개입니다.

- **대시보드:** CPU, RAM, DISK 게이지와 최근 1시간 추세 차트. 임계치 초과 시 화면이 붉게 바뀌고 경고음이 울립니다.
- **프로세스:** 실시간 목록, 열 정렬, 감시 대상 강조, 점유 상위 항목 표시. 이름을 더블클릭하면 상세 정보(경로, 명령줄)를 봅니다.
- **프로세스맵:** 부모·자식 관계를 노드와 곡선으로 그립니다. 전체, 감시 대상 관련, 검색 일치 관련, 선택 프로세스 관련으로 범위를 바꿔 볼 수 있습니다.
- **점검실행:** FAS·EAI 점검 배치(일일, 상세, 월간, 연간, 로그 백업, PC 상태 수집)를 골라 실행하고 출력을 실시간으로 봅니다.
- **결과조회:** 날짜와 실행 시각별 결과(TXT, CSV)를 봅니다. CSV의 상태 값(PASS, FAIL, WARN)은 색으로 구분합니다.
- **로그:** 누적 로그를 보고 검색합니다.
- **스크립트 편집:** 점검 배치 파일을 화면에서 고쳐 저장합니다. 내장 원본으로 되돌리는 기능이 있습니다.
- **작업 스케줄러:** Windows 작업 스케줄러의 작업 목록과 상태를 봅니다. (PowerShell로 조회)
- **네트워크:** `netstat` 결과로 연결 목록과 포트 상태를 봅니다. 잘 알려진 포트에는 서비스 이름을 붙입니다.
- **핑:** 여러 대상을 등록해 주기적으로 핑을 보내고, 손실률과 응답 시간으로 상태(정상, 주의, 불량)를 나눠 보여 줍니다. 응답의 TTL로 OS를 짐작합니다.
- **설정:** 감시 프로세스, 임계치, 감시 드라이브, 경고음, 감시 주기, 점검 배치 경로를 바꾸고 저장합니다.
- **단축키:** F11로 전체 화면을 전환합니다.

## 실행 파일 사용법

- `checkserver.exe`를 실행합니다. 창 기본 크기는 400×400입니다.
- `userset.json`은 **exe와 같은 폴더**에 있어야 합니다. 없으면 기본값으로 만듭니다.
- 첫 실행 시 `C:\checkPMI\`에 점검 배치 파일이 없으면 내장 원본으로 만듭니다.
- 생성되는 파일
  - `C:\checkPMI\logs\<yyyymmdd_hhmmss>\check_result.txt` / `.csv`: 점검 결과
  - `C:\checkPMI\logs\system_accumulated.log`: 누적 로그
  - `C:\checkPMI\save360\`: 로그 백업 결과
- 일부 기능(작업 스케줄러, 프로세스 상세, 네트워크)은 관리자 권한이 필요할 수 있습니다.
- Windows 전용입니다 (`cmd`, `powershell`, `netstat`, `ping`, `kernel32 Beep`을 씁니다).

## 빌드 방법

```
cd module_E_CheckServer_Rust
cargo build --release
```

- Rust 최신 stable(에디션 2024 지원 버전)이 필요합니다.
- MSVC 링커를 쓰므로 Windows SDK가 설치되어 있어야 합니다. 모듈 C의 "빌드 방법"을 참고하세요.
- 빌드 전에 `assets/checkPC.bat`, `assets/checkPC.ps1`이 있어야 합니다 (위 "상태" 참고).

## 모듈 B·D와의 차이

| 항목 | 모듈 B (Python) | 모듈 D (Rust) | 모듈 E (Rust 확장) |
|---|---|---|---|
| 탭 수 | 6 | 6 | 11 |
| 창 크기 | 400×400 | 1000×720 | 400×400 |
| 프로세스맵, 작업 스케줄러, 네트워크, 핑 | 없음 | 없음 | 있음 |
| 스크립트 편집 | 없음 | 없음 | 있음 (내장 원본으로 복원 가능) |
| 점검 배치 | 내장 + 경로 설정 | 내장 2개 | 내장 8개 |
| 결과 조회 날짜 선택 | 달력 위젯 | 날짜 입력 | 날짜 입력 |

- 감시 주기, 임계치, 경고 판정, 로그 기록 시점은 모듈 B와 같은 기준입니다.
- 프로세스 소유자 열은 없습니다. sysinfo로 소유자를 바로 가져오기 어려워 상세 창에서 생략했습니다.

## 알려진 제한

- **빌드 실패 가능성:** `assets/checkPC.bat`, `assets/checkPC.ps1`이 저장소에 없어 소스만으로는 빌드되지 않습니다.
- **빌드 산출물 포함:** `build/checkserver/`(PyInstaller 중간 산출물, 수십 MB)와 루트의 `checkserver.exe`가 저장소에 함께 올라가 있습니다. 공개 저장소에는 `.gitignore`로 제외하는 것이 좋습니다.
- **내부 IP 주소:** `userset.json`과 내장 점검 배치에는 **내부 IP 주소가 그대로 들어 있습니다.** 과제 보안 기준상 공개 저장소에 올리기 전에 마스킹해야 합니다.
- **검증 범위:** 실서버 점검, 경고음, 관리자 권한 기능, 핑 대상 응답은 실서버 없이 확인하지 못했습니다.
- 점검 배치 출력은 CP949(한글 Windows 기본)로 해석합니다. UTF-8이면 자동으로 UTF-8로 읽습니다.
